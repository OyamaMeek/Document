# 用 Vibe Coding 设计 UI

你可以让 AI 写界面代码，自己负责决定用户要完成什么、页面先展示什么，以及修改到什么程度。第一次练习，选一个你确实会用的页面，做完它的完整操作流程。

这份指南根据本地《人人都是 UI 设计师》《网页动效词典》上中下篇，以及 X_post 中的视觉规则和 AI 设计词典整理。我把其中的图片设计方法转成了网页设计步骤，并用 W3C、MDN 文档核对了文字对比度、弹窗焦点与减少动态的要求。

全文使用一个练习项目“学习资料收藏页”。做完后，你应当能添加一条真实学习链接，搜索它，切换阅读状态，并在手机宽度下完成同样操作。练习里的尺寸、颜色和时长都是起步参数，可以按内容调整。

## 1. 先准备能开始工作的条件

准备一个可以读写项目文件、运行代码的 AI 编程工具，以及能打开本地网页的浏览器。沿用你已经在用的工具即可。普通聊天工具可以讨论设计，但生成代码后仍需要有人运行和检查。

已有项目时，让 AI 先读项目说明、依赖和组件。空目录时，先告诉它你想做的页面，让它说明最小实现和启动方式。第一轮不必先安装一整套设计工具。

初次练习只准备三样东西。

- 一段具体需求，说明谁使用、完成什么任务。
- 一到两张你喜欢的参考图，分别注明想借鉴的部分。
- 两三条你自己的资料链接，供页面做好后实际输入。

如果暂时没有参考图，可以先完成灰度布局，再决定视觉方向。不要为了找参考图推迟全部工作。

本次练习不需要登录、云同步或部署。资料保存在当前浏览器，只用于学习交互；清理浏览器数据可能丢失记录，换设备也不会同步。使用真实产品时，需要单独设计数据保存与恢复方式。

## 2. 把“好看”拆成可以判断的要求

三组资料分别能帮你解决不同问题。

| 资料 | 在实际工作中的用法 |
| --- | --- |
| 《人人都是 UI 设计师》 | 检查层级、间距、按钮主次、文字可读性和空状态 |
| X_post 的 AI 设计词典 | 描述位置、大小、字体、颜色，并限定修改范围 |
| X_post 的视觉规则文章 | 把已经确定的设计写入同一份规则文件，后续持续复用 |
| 《网页动效词典》 | 描述触发条件、运动过程、结束状态和使用限制 |

你每次给 AI 的任务，都尽量包含以下内容。

```text
目标
谁使用这个页面，要完成什么操作。

结构
页面有哪些区域，按什么顺序排列，最重要的内容是什么。

视觉
字体、颜色、间距、圆角与图片分别怎么处理。

行为
点击之后发生什么，成功和失败分别显示什么。

边界
这次允许修改哪些部分，已经确定的部分保留哪些。

验收
我怎样操作，才能确认这一轮完成。
```

不用每一轮都重复整份需求。第一次说明完整目标，之后只补充当前要改变的内容，并引用已经保存的规则。

## 3. 第一轮先写清页面任务

“做一个学习平台”留下了很多未决定的事情。先缩到一个页面，写出用户进入后最先要做的操作。

收藏页的主要任务是添加和找回资料。页头放页面名称和“添加资料”，下面放搜索、阅读状态筛选，再往下显示资料列表。不要在首屏加入与这个任务无关的宣传大图。

把下面这段发给 AI。此时先让它整理设计，等你读过后再执行代码修改。

```text
我要做一个给自己使用的学习资料收藏页。

用户要能添加资料标题和网址，搜索资料，按全部、未读、已读筛选，切换阅读状态，并打开原文。

页面结构依次为页头、搜索与筛选、资料列表。
页头的主要操作是“添加资料”，其他操作降低视觉强调。
先设计没有资料时的页面，再设计已有资料和搜索无结果的页面。

已有项目先检查依赖、样式和组件，沿用现有能力。
空项目请提出能够本地运行的最小实现。
本次练习使用浏览器本地保存，不做登录、云同步或部署。

先给出页面区域、主要操作流程、状态清单和启动方案，暂不修改代码。
仅在缺少的信息会明显改变实现时提问。
```

读它的回答时，检查有没有凭空增加账户中心、统计看板或复杂分类。把不需要的内容删掉。确认主要流程后，明确回复“按这份方案执行”，再进入下一轮。

这一轮完成的标志是，你能说出一条完整操作路径。

> 打开空收藏页，点击添加，输入标题和网址，保存后看到资料，搜索找到它，再把它标为已读。

## 4. 参考图要说明借鉴什么

X_post 的设计边界文章强调，需要给每张参考图安排明确用途。应用到 UI 时，可以让图 A 提供布局，图 B 提供颜色和字体；两张图存在冲突的地方，自己决定采用哪一项。

选择参考时，先看内容与任务是否相近。长文章、管理列表、产品宣传页的排版需要不同。你喜欢某个产品的颜色，可以只借鉴配色，不必把它的首屏结构一起搬来。

```text
图 A 作为布局参考，只借鉴页头、工具栏和列表的区域关系。
图 B 作为视觉参考，只借鉴背景色、文字层级和圆角尺度。

保留我的中文内容和收藏流程。
Logo、插画、图片、原文案不在复用范围内。

请先把你观察到的规则整理成表格。
无法从截图准确确定的字体名称、字号、色值请标为估计。
如果两张图有冲突，指出冲突，并给出适合收藏页的一个建议。
先完成文字分析，不修改代码。
```

截图能说明静态布局。动效需要补充操作过程，可以由你描述，或者在允许的情况下提供录屏。单张截图无法确定动画时长，也不能证明手机和键盘操作正常。

AI 从截图估计出的参数也需要检查。尤其是品牌字体、背景图片和图标，不要把识别结果直接当作可用资产。

## 5. 先让灰度页面成立

《人人都是 UI 设计师》建议先用灰度处理层级。收藏页可以先完成真实功能，用黑白灰检查主要按钮、标题和辅助信息的关系。

这个顺序能让你发现布局问题。所有按钮都很醒目、标签和输入框离得一样远、表单横跨整块屏幕，这些问题都应当先处理。

```text
按已经确认的方案，实现能够本地运行的收藏页。
这一轮使用黑白灰，不加入装饰图片和入场动画。

完成添加、搜索、阅读状态筛选、切换已读和打开原文。
数据实际保存在浏览器本地，刷新后能恢复。
保存失败时保留用户输入并显示原因，不能显示成功。
网址仅接受有效的 http 或 https 地址。

主内容最大宽度先用 1120px，居中展示。
表单最大宽度先用 560px，窄屏下保留两侧空间。
以 4、8、12、16、24、32、48px 作为间距候选。
标签到输入框的间距小于两组字段之间的间距。

只让“添加资料”具有最强的按钮强调。
数据展示优先区分资料标题、网址和阅读状态。
所有输入框保留可见标签，不能只靠 placeholder。

请实际运行页面并检查完整流程，说明启动地址、验证结果和未完成项。
本轮不截图或进行视觉检查。
```

打开页面后，先只观察三件事。主操作是否容易找到，同一组信息是否靠近，正文和网址是否容易阅读。确认这些关系之后再处理配色。

资料一多，卡片可能占用太多空间。收藏页以快速扫描为主时，可以使用紧凑列表。页面结构由内容决定，不必要求每种信息都套一层卡片。

## 6. 把视觉决定保存在 visual-rules.md

X_post 的视觉规则文章提出，把重复使用的设计决定保存成文件。用到网页项目里，你可以让 AI 将它与现有样式变量、组件对应起来。

Markdown 文件本身不会自动更新代码。规则修改后，需要明确让 AI 同步实现并核对。已有项目已经有可靠的设计规范时，继续维护原规范，避免新增一份互相冲突的说明。

下面是一份适用于练习的内容，可以保存为 `visual-rules.md`。

```markdown
# 学习资料收藏页视觉规则

## 气质与内容

- 中文工具页面，清楚、安静，便于扫描。
- 页面重点为资料标题和添加操作。
- 不加入与查找资料无关的宣传区。

## 布局

- 主内容最大宽度 1120px，桌面两侧至少 32px，手机两侧 16px。
- 先用 768px 作为布局调整参考，内容放不下时继续调整。
- 小屏工具栏允许换行，资料改为单列，保持正常纵向滚动。
- 添加表单最大宽度 560px，窄屏适配可用宽度。

## 文字

- 使用项目现有中文无衬线字体；空项目采用系统字体。
- 页面标题先用桌面 32px、手机 24px，字重 600。
- 正文先用 16px、行高 1.6；辅助文字先用 14px。
- 主要文字 #17201C，次要文字 #526159。
- 相邻不同字号文字按基线排列。
- 长标题换行，长网址不能撑破容器。

## 颜色

- 页面背景 #F6F8F6，内容表面 #FFFFFF。
- 主按钮 #216E4E，文字 #FFFFFF。
- 选中或成功提示可用浅绿 #E8F3EC 配深绿 #18543C。
- 错误提示使用文字说明，颜色只辅助传达。
- 按现有组件需要补齐悬停、按下、禁用和焦点状态。
- 实现时计算文字与实际背景的对比度。

## 组件

- 按钮和输入框圆角 8px，面板圆角 12px。
- 同类组件复用相同样式。
- 图标使用同一套，普通图标先用 20px。
- 主次按钮通过填充、边界与字重区分。
- 分组优先使用间距和背景差；输入框边界仍需清楚。

## 动效与边界

- 优先复用项目能力，简单反馈用 CSS。
- 按钮状态过渡先用 160ms，弹窗先用 200ms。
- 所有关键操作支持触屏与键盘。
- 减少动态时关闭装饰性位移与缩放，内容直接可见。
- 本项目不用霓虹、玻璃效果、持续追光和正文逐字播放。
```

接着发出实施指令。

```text
请读取 visual-rules.md，并应用到已经完成的收藏页。
复用项目现有样式变量和组件，让同类颜色、间距、圆角有共同定义。
保留已完成的功能和数据处理，只调整这一轮涉及的样式。
检查规则与实际实现是否一致，并列出发生冲突的项目。
```

颜色数量不要机械限制成几个 HEX。UI 需要中性色的不同深浅，也需要状态色。先保证每种颜色有用途，再按现有控件补齐需要的色阶。

“浅底深字”是一种配色手段，仍需计算对比度。WCAG 2.2 AA 对普通文本通常要求至少 `4.5:1`，符合其大字定义的文本至少 `3:1`。本指南给出的色值是候选值，实现时要连同实际背景和状态一起检查。[W3C 文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

## 7. 把状态当作页面的一部分

完整 UI 要覆盖用户刚进入、操作中和操作失败时看到的内容。最容易漏掉的是空状态，以及搜索结果为空时的恢复入口。

| 状态 | 收藏页应该显示什么 | 检查动作 |
| --- | --- | --- |
| 还没有资料 | 简短说明和“添加第一条资料” | 在无记录的浏览器环境打开 |
| 已有资料 | 标题、网址、阅读状态和操作 | 添加一条真实链接 |
| 搜索无结果 | 说明当前没有匹配结果，提供清空搜索入口 | 搜索不存在的词 |
| 表单输入无效 | 字段旁的具体说明，保留其他输入 | 留空标题或输入无效网址 |
| 保存成功 | 新记录出现，表单关闭，给予成功反馈 | 完成一次有效提交 |
| 保存失败 | 说明未保存，保留表单内容，允许重试 | 在确实存在的存储失败条件下检查 |
| 切换阅读状态 | 文字和控件状态更新，筛选结果同步 | 在未读筛选中标记已读 |

本地保存练习没有网络请求，不需要人为等待一秒来播放加载动画。以后接入远程服务时，再根据真实请求增加加载、失败和重试状态。骨架屏适用于已知结构的异步内容，进度条应展示能够计算的进度。

```text
请检查收藏页的空状态、正常状态、搜索无结果、表单错误、保存成功和保存失败。

无资料与无搜索结果使用不同文案。
无资料时隐藏没有用途的筛选控件；无搜索结果时保留搜索与清空入口。
输入错误在对应字段旁说明原因，错误不能只用红色表达。
保存结果以真实写入结果为准，失败时保留输入。
状态筛选与阅读状态切换保持一致。

请通过实际操作和适用测试核对这些行为。
无法真实触发的失败条件要说明，不能把未检查写成通过。
```

《人人都是 UI 设计师》中删减标签的方法主要用于数据展示。表单里的标签要保留，技术指标也需要清楚的名称。把规则用在它对应的场景里。

## 8. 用动效解释操作

《网页动效词典》把动效拆成工具、触发、效果和 UX 规则。写提示词时，再补上对象、参数和结束状态，就能减少 AI 自行猜测的部分。

```text
对象 + 触发条件 + 怎样变化 + 时长与缓动 + 结束状态 + 输入方式与减少动态处理
```

### 先掌握这些常用词

| 名称 | 表现 | 可以放在哪里 |
| --- | --- | --- |
| Fade 淡入淡出 | 改变透明度 | 提示、遮罩、内容切换 |
| Slide 滑入滑出 | 沿一个方向移动 | 抽屉、底部面板 |
| Scale 缩放 | 小幅改变大小 | 按下反馈、弹窗出现 |
| Stagger 交错出现 | 一组元素错开开始时间 | 少量卡片首次入场 |
| Line reveal 按行显现 | 标题一行一行出现 | 宣传页短标题 |
| Layout animation 布局过渡 | 从旧位置移到新位置 | 删除或筛选后的列表 |
| Toast 轻提示 | 短暂展示操作结果 | 保存、复制 |
| Duration 时长 | 一次动画持续多久 | 所有动画 |
| Easing 缓动 | 速度怎样变化 | 进入、退出和回位 |

收藏页可以先只做按钮反馈、添加弹窗和保存提示。列表能立即更新、文字保持稳定，已经足够支持主要任务。

### 给 AI 一段完整的动效要求

```text
只为收藏页添加以下动效，保持布局和配色不变。
优先复用项目方案，简单反馈采用 CSS，不新增动画依赖。

按钮悬停时改变背景色，过渡 160ms。
键盘聚焦显示清楚的 focus-visible 焦点环。
按钮按下时缩放至 0.98，松开恢复；触屏也有反馈。

点击“添加资料”后，遮罩淡入，弹窗从下方 8px 移动到最终位置并淡入。
弹窗入场 200ms、ease-out，关闭 160ms。
打开后焦点进入弹窗，Tab 和 Shift+Tab 在弹窗内移动。
支持 Escape 和可见取消按钮关闭，关闭后焦点回到触发按钮。
背景暂时不可操作，也不能滚动。
未保存内容需要有明确的放弃处理，不能误触遮罩就丢失输入。

保存真正成功后显示“已保存”轻提示，停留约 3 秒。
保存错误保留在表单中，直到用户修正或关闭。

开启 prefers-reduced-motion 时取消缩放和位移，直接呈现最终状态。
必要的成功、失败和焦点反馈继续保留。
```

弹窗需要同时管理焦点和背景交互。W3C APG 说明了焦点进入、Tab 在弹窗内循环、Escape 关闭，以及关闭后的焦点返回规则。实现时优先使用项目已有的可靠弹窗组件。[W3C 弹窗模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

`prefers-reduced-motion` 用来检测用户减少非必要运动的偏好。加上这条规则以后，还要实际检查内容是否直接可见，避免取消动画后仍停留在透明的起始状态。[MDN 减少动态说明](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)

### 需要表现力时再加入额外效果

品牌介绍页或作品集可以选择一个与内容有关的主效果。比如用按行显现强调一句短标题，用共享元素转场解释卡片怎样进入详情。

视差、磁吸按钮、倾斜卡片和光标跟随都需要额外处理手机、键盘和减少动态。先检查它有没有影响文字阅读和点击，再决定是否保留。

另外要分清两种滚动行为。

- 进入视口后播放一次，动画触发后自己完成，适合卡片入场。
- 进度跟随滚动，滚到哪里动画进行到哪里，适合产品拆解等叙事。

只说“加一个滚动动画”无法确定这两个行为。

## 9. 把不满意的感觉改写成局部任务

第一次结果通常需要修改。先指出具体位置，再说明现象和期望；一轮集中处理一类问题，观察结果后再继续。

| 你看到的现象 | 可以发给 AI 的要求 |
| --- | --- |
| 页面很乱 | 降低辅助信息的视觉重量，减少装饰，拉开模块间距；保留资料字段 |
| 标题不突出 | 保持正文字号，增强标题字重，减弱旁边辅助文字的强调 |
| 页面空得散 | 收窄内容区域，将相关控件集中，减少同组元素间距 |
| 卡片显得厚重 | 减弱阴影和背景反差，检查边框是否重复表达分组 |
| 颜色刺眼 | 保持主色方向，降低大面积背景饱和度，检查文字对比度 |
| 手机不好用 | 工具栏换行，资料单列，长网址换行，主要操作保持可见 |
| 动画拖沓 | 缩短时长和交错间隔，用户操作后立即显示结果反馈 |

X_post 提出的 Reference、Fixed、Variable、Avoid、Consistency 可以用于限制这一轮范围。

```text
只调整资料列表的信息层级。

当前问题是网址、状态和标题同样醒目，扫描时难以先找到资料名称。

固定项
保留页面区域顺序、资料字段、已有功能和 visual-rules.md 的配色。

可变项
只修改列表项内部的字重、文字颜色和间距。
标题作为第一阅读层级，网址作为辅助信息。
阅读状态采用轻量标签，文字依然清楚。

排除项
本轮不更换布局，不增加统计区和动效，不删除数据。

验收
长标题能够换行，网址不会撑破容器。
同类资料使用相同样式，未读与已读有明确文字区分。
修改后重新运行搜索和状态筛选检查。
```

修改前保留一个可恢复版本。让 AI 总结实际改动，并检查是否越出了限定范围。提示词里的“固定”提供约束，最终仍需要通过差异和运行结果核对。

## 10. 专门检查手机和长内容

X_post 中的画幅比例适合图片、封面和 Banner。真实网页需要适应可用宽度、文字数量和用户操作，不能把整页当成一张固定比例的图缩小。

为练习页至少观察桌面和手机两种宽度。具体设备会变化，可以先使用 1440px、768px、390px，再补查 320px 的窄屏。断点由内容能否合理排列决定。

```text
请检查 1440、768、390 和 320px 宽度下的收藏页行为。

桌面内容有最大宽度，表单不会横向拉满。
小屏标题独立调整字号，正文仍能舒适阅读。
工具栏允许换行，搜索框和主操作不能被遮挡。
长中文标题、长英文单词和长网址均不造成页面横向溢出。
弹窗内容超出高度时可以滚动，关闭和提交入口仍可到达。
关键操作支持点击和键盘，不能只在 hover 后出现。

先完成运行与行为检查，明确报告结果。
本轮不截图；视觉验证另行授权。
```

如果页面确实需要横向数据表，可以让表格区域单独滚动，并保留列名。收藏页的普通文字内容通常可以直接换行。

## 11. 让 AI 按用户路径验收

“构建成功”能证明代码通过构建，页面是否符合视觉要求仍需要打开查看。先检查操作流程，再检查外观，两类结果分别记录。

你可以将下面的任务交给 AI 做行为验收。

```text
请按首次使用者的路径检查收藏页。

1. 在无资料状态下打开页面，确认能找到添加入口。
2. 添加一条我提供的真实资料链接，确认显示标题、网址和未读状态。
3. 刷新页面，确认资料仍然存在。
4. 按标题搜索，再清空搜索，确认列表恢复。
5. 切到未读筛选，将该资料标为已读，确认它离开未读结果。
6. 切到已读筛选，确认可以找到它并打开原文。
7. 检查空标题和无效网址，确认错误说明具体且输入保留。
8. 使用键盘打开、操作和关闭添加弹窗，核对焦点返回。
9. 检查窄屏溢出和减少动态模式下的内容可见性。

运行项目已有的相关测试、类型检查和构建。
必要时补充能验证真实保存与筛选行为的最小测试。
逐项报告通过、失败或未检查，并提供实际命令或操作证据。
未接入后端、本地保存的限制需要明确说明。
本轮不截图或做视觉判断。
```

你准备好让 AI 检查外观时，再明确授权。

```text
现在授权对本地收藏页进行视觉验证。
请打开实际运行页面，在桌面和手机视口截图并检查。
覆盖空状态、已有资料、添加表单和输入错误。
记录页面地址、视口、截图文件以及观察到的问题。
逐项核对 visual-rules.md 和参考图中已指定的借鉴部分。
先报告问题；修改只限于已经确认的设计要求。
```

不具备浏览器或截图能力时，AI 应说明缺少哪些检查。你也可以自己打开页面，指出某个位置的问题，再让它定点修正。单次截图不能验证动效过程，动画还需要实际触发和观察结束状态。

## 12. 把二十条 UI 原则变成检查表

这一表根据《人人都是 UI 设计师》二十条规则改写，用于检查当前页面。无需每次把所有条目都交给 AI，按正在解决的问题选用。

| 原则 | 当前页面可以怎样检查 |
| --- | --- |
| 选择设计个性 | 字体、圆角、配色和文案是否表达相近的气质 |
| 先处理灰度 | 去掉品牌色后，主次关系是否仍然清楚 |
| 综合建立层级 | 字号、字重、颜色是否共同区分重要程度 |
| 减弱竞争元素 | 辅助导航和次要操作是否过于醒目 |
| 删减冗余标签 | 数据展示是否存在可以省去的重复字段名；表单标签保留 |
| 按重要程度设计按钮 | 同一区域是否有清楚的主要、次要和辅助操作 |
| 给足留白再调整 | 内容是否贴边，同组元素是否仍然聚合 |
| 限制内容宽度 | 表单和段落是否被过度拉宽 |
| 区分组内与组间距离 | 标题、说明、字段的归属是否容易辨认 |
| 独立调整手机尺寸 | 小屏标题、间距与布局是否各自适配 |
| 联合检查行长和行高 | 中文正文换行是否舒适，段落是否过宽或过密 |
| 不同字号按基线排列 | 标题旁的小字是否与它自然排在同一行 |
| 为实际用途准备色阶 | 文字、背景、选中和错误状态是否各有适合的色值 |
| 浅底深字并计算对比度 | 标签是否清楚，正常与悬停文字是否可读 |
| 状态增加文字或图标 | 去掉颜色后能否分辨错误、成功和阅读状态 |
| 局部使用强调色边框 | 当前项是否可以通过一小段强调表达，无需大面积染色 |
| 图片文字先处理背景 | 亮部和暗部之上的文字是否都清楚，是否需要蒙版或独立文字区 |
| 尊重图标与截图尺寸 | 图标是否被盲目放大，产品图是否缩小到文字无法辨认 |
| 克制使用分隔线 | 背景、间距和边框是否重复表达同一种分组 |
| 优先设计空状态 | 新用户是否能看到有用说明和下一步操作 |

原资料里一些数字是排版经验，使用时需要结合语言和内容。例如英文行长的字符数不能直接换成同样数量的汉字；中文正文需要按实际显示效果调整宽度与行高。

## 13. 第一次练习按这个顺序做

| 轮次 | 发给 AI 的任务 | 你确认后再继续的内容 |
| --- | --- | --- |
| 1 | 整理需求与状态 | 页面任务和完整操作路径 |
| 2 | 分析参考图 | 每张图负责的部分与需要保留的内容 |
| 3 | 实现灰度页面 | 功能能运行，层级和分组清楚 |
| 4 | 保存并应用视觉规则 | 字体、配色、间距与组件一致 |
| 5 | 补齐状态与手机适配 | 空状态、错误和窄屏行为可用 |
| 6 | 加入必要反馈动效 | 操作及时响应，键盘和减少动态可用 |
| 7 | 完成行为与授权后的视觉检查 | 有检查证据，剩余问题写清楚 |

如果某一轮不满意，就使用第 9 节的局部修改格式。已经确认的设计继续保留，直到这一处问题解决。

以后新增一个详情页时，把现有 `visual-rules.md` 和相关组件交给 AI，再说明新页面的信息和操作。需要改变规则时，先更新规范，再让所有使用它的页面同步。
